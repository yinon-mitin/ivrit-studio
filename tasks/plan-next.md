## Decisions to confirm (defaults in bold)
1. **The centre line applies to everything that names the section being read on a laptop** (the flowing titles, the page-bar label, the ruler label), so they never disagree on one screen. Phones keep today's line under the bar. Alternative: only the flowing titles move.
2. Install icon: the Hebrew letter **א on the paper colour, in the accent blue** (Heebo, the font already on the site). Four PNGs are generated by a dev script from the font and committed.
3. Install banner: shown on touch phones only, **on the second visit or after 30 s on a page**, never in standalone mode, never in print. Dismiss snoozes it for **30 days**. Android/Chrome gets a real "Install" button; iOS Safari has no install event, so it gets a one-line hint (Share → Add to Home Screen).
4. Offline service worker (T18): **do it later, after T17**, as its own task, because it is the only way to beat GitHub Pages' `max-age=600` and to work in a classroom with no signal. It carries a stale-content risk, so it needs your explicit go.
5. GitHub link: **a small muted footer line at the bottom of the contents page only** (owner, 2026-10-21: not on every page). "Source on GitHub" with the GitHub mark, opens in a new tab, hidden in print. Not in the header, so it never competes with search or the toggles.
6. SPEC: a new `install` module is outside the capability map, which SPEC lists under "ask first". Approving this plan counts as that approval; T16 and T17 update SPEC in the same task.

## Architecture Decisions
- **One reading line.** `core/scroll.js` gets a pure `readingLine(viewportHeight, stickyHeight, centred)` and a rule that at the very end of the page the last section counts as being read. `main.js` asks it once per update and passes the result to `currentAnchor`. Without the end rule a short last section could never reach the centre and its title would never light up.
- **Install decision is a pure function.** `core/install.js` gets `installOffer({ standalone, touch, ios, canPrompt, visits, firstSeen, dismissedAt, now })` returning `'prompt' | 'ios-hint' | 'none'`, fully unit-tested. The DOM side (`ui/install.js`) only listens for `beforeinstallprompt` and `appinstalled`, draws the banner and calls `prompt()`. State lives in `localStorage` through `storage.js` only, parsed field by field like `settings.js`, so a broken value never breaks the site.
- **No new external requests.** `manifest-src` and `worker-src` fall back to `default-src 'self'` in the CSP, so no CSP change is needed. The favicon becomes an inline SVG data URI (`img-src` already allows `data:`), which keeps the current zero-request favicon. The manifest and PNG icons are same-origin; their size counts against the 200 KB first-load budget and is measured.
- **Installability is tested, not assumed.** In Chromium, e2e reads `Page.getAppManifest` and `Page.getInstallabilityErrors` over CDP and expects no errors. The iOS path is tested in the webkit-iphone project.
- **The footer link is DOM-built.** The GitHub mark is an SVG made with `createElementNS`, as the search icon is (no HTML sinks: `.semgrep.yml` forbids them). Text and `aria-label` come from `i18n.js` in both languages.
- **Performance work follows numbers.** T19 produces a baseline file; T20 only does what the baseline shows is worth it. No new tooling dependency (Lighthouse etc. would be "ask first"); Playwright's CDP metrics and `PerformanceObserver` are enough.

## Risks and Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| A short last section never reaches the centre, so its title never becomes current | Med | End-of-page rule in `readingLine`/`updatePosition`; unit test and an e2e that scrolls to the bottom and expects the last title current |
| Page bar, ruler and titles disagree about the current section | Med | They share one reading line on laptops (decision 1); e2e checks the three labels agree at a mid-section scroll |
| Existing `flow-toc` e2e flakes more once the switch point moves (it failed intermittently, also on a clean `HEAD`, while the 2026-10-21 changes were checked) | Med | First make the test wait on state instead of timing (`expect.poll` is used already); run it 5 times before and after T14; do not loosen assertions |
| Install banner annoys readers or covers the Hide toggle | Med | Shown once per 30 days at most, bottom of the screen, dismissable, never over the sticky bar; e2e checks no overlap and no overflow at 360×640 |
| `beforeinstallprompt` is Chromium-only; iOS gives no event | Med | Two code paths by design (button vs hint). The iOS hint is judged on a real iPhone at Checkpoint F |
| Chrome may still require a service worker for the install prompt | Med | T16 verifies with `getInstallabilityErrors`. If an error names the service worker, T18 moves before T17 |
| Service worker serves stale lessons after a deploy | High | Only if the owner says go. Network-first for `index.html` and `data/`, cache-first for fonts; versioned cache name; update path tested; easy unregister |
| GitHub footer fails axe contrast in dark theme | Low | Uses the existing `--muted` token (already AA on both papers); axe runs on every part in both themes |
| Icon PNGs bloat the first load | Low | Chrome does not fetch icons on page load; only the manifest (~1 KB) counts. Measured in T16 |
| Preload hints drift out of date when a module is added (no build step) | Low | Unit test compares the hint list with the real import graph |

## Answer: other UI features and optimizations

Basis: I read the code and measured what is cheap to measure (no profiler run yet; T19 does that). Facts used: first load is 108 KB transferred, the fonts are 24 and 29 KB, `app.css` is 26 KB, `data/` is 71 KB across 11 sections (a part page loads only its own sections), GitHub Pages serves everything with `cache-control: max-age=600` and that cannot be changed from the repo. I did not run the `agent-skills:webperf` auditor persona; Task 19 is where to run it, against the real numbers.

**Performance (ordered by expected value)**
1. **Repeat visits and offline (T18).** The 10-minute cache is the real limit for a site people open every lesson. A service worker is the only way to make the second visit instant and to work with no signal.
2. **A shorter request chain.** The browser fetches `main.js`, then ~20 imported modules, then `data/index.json`, then the part's section files, one step after another. `<link rel="modulepreload">` for the modules and `<link rel="preload" as="fetch" crossorigin>` for `data/index.json` flatten that without a build step (T20, if the baseline shows a gain).
3. **`content-visibility: auto` on sections** of long parts, with a size hint, so off-screen sections cost no layout. The Nikud toggle re-renders the whole part (the reader is kept in place), so T19 also measures that interaction (INP) before changing anything.
4. **Make the budget wider than weight.** Today the bar covers bytes only. A cheap addition: e2e assertions for CLS ≈ 0 and LCP on a throttled profile, so a regression in layout or load shows up in CI. This changes `CONSTRAINTS.md`, so it is "ask first".

**UI features (all fit the "reference, not trainer" scope; sorted by value for a learner)**
1. **My words:** a star on each entry, a "starred only" filter and printing of the starred list. Saved in `localStorage` through `storage.js`. This is the most useful thing missing for a cheat-sheet used between lessons.
2. **Text size for Hebrew** (A−/A+): useful on phones and for reading cursive.
3. **Permalink to an entry** with a highlight when opened, plus tap-to-copy for the Hebrew word.
4. **Better search:** highlight the matched part, a shareable `#/search/<query>` address, and treating final letters as their plain forms (ך = כ) so a half-typed word still matches.
5. **Laptop keyboard:** `j`/`k` for next/previous section (the flowing titles already show where you are). **Phone:** a back-to-top button after a long scroll.
6. **Print chooser:** print one section, not the whole part.

Not suggested: pronunciation audio. SPEC lists TTS under "Never" unless the author reopens it; if you do, it is a separate decision with its own cost (no external services, so browser `speechSynthesis` only, and Hebrew voices are uneven across devices).
